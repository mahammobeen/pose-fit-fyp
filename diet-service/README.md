# PoseFit Diet Plan Recommendation Microservice

Content-based diet recommendation engine for the **PoseFit** MERN + FastAPI fitness platform. It generates multi-day Pakistani meal plans that match a user's daily calorie and macro targets.

## Architecture Overview
- **Problem Formulation**: Unsupervised nearest neighbor retrieval (k-NN) paired with constrained multi-objective portion optimization.
- **Dataset**: 495 Pakistani food items (100g nutrient basis), expanded into per-slot rows by meal type.
- **Core Components**:
  - Custom NumPy/SciPy implementations of `StandardScaler`, `OneHotEncoder` and `NearestNeighbors` (no scikit-learn dependency). They live in `src/recommender.py` and are serialized with joblib.
  - k-NN retrieval over a 10-dimension feature vector: 4 macros (calories, protein, carbs, fats), protein ratio, and a weighted one-hot meal slot (weight 0.35).
  - Rule-based beverage layer: Breakfast and Snack slots get a 150g drink chosen by fitness goal (lose, maintain, gain). Its macros are subtracted from the slot target before the main dish is chosen.
  - Portion optimizer: tries portions from 50g to 300g (0.5x to 3.0x) per dish and minimizes a weighted loss (calories 0.40, protein 0.25, carbs 0.20, fats 0.15). Lunch and Dinner can use a 2-dish combo when a single dish fits poorly.
  - Multi-day variety tracker: avoids repeating dishes across days and picks randomly among the top candidates, so regenerating gives a new plan.
- **Daily slot split**: Breakfast 25%, Lunch 35%, Dinner 30%, Snack 10%.

## Directory Structure
```
python-service/
├── data/
│   └── pakistani_food_dataset_100g.csv   # 495 Pakistani food items (100g basis)
├── models/
│   └── diet_recommender.joblib           # Single bundle: k-NN model, scaler, encoder, food metadata
├── src/
│   ├── __init__.py
│   ├── data_pipeline.py                  # Cleaning, Atwater check, meal type explosion, feature engineering
│   ├── recommender.py                    # Custom scaler/encoder/k-NN, beverage manager, portion optimizer, plan generator
│   └── train.py                          # Reference/Query split, 5-fold CV tuning, training, serialization
├── tests/
│   ├── __init__.py
│   ├── test_all.py                       # Pipeline tests, API tests, end-to-end profiles, accuracy benchmark
│   └── accuracy_report.csv               # Per-slot accuracy results generated by the benchmark test
├── main.py                               # FastAPI application entry point
├── requirements.txt                      # Python dependencies
└── README.md                             # Service documentation
```

## Execution & Usage

### 1. Install Dependencies
```bash
pip install -r requirements.txt
```

### 2. Run Data Pipeline & Model Training
```bash
python src/data_pipeline.py
python src/train.py
```
`train.py` creates `models/diet_recommender.joblib`.

### 3. Run Test Suite
```bash
pytest tests/ -v
python tests/test_all.py
```
Running `test_all.py` directly also prints the end-to-end profile results and regenerates `tests/accuracy_report.csv`.

### 4. Start the FastAPI Microservice
```bash
uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```
Interactive Swagger API documentation is available at: `http://127.0.0.1:8000/docs`

## API Contract

### GET `/health`
Returns service status and whether the model is loaded.
```json
{
  "status": "healthy",
  "service": "PoseFit Diet Plan Recommendation Microservice",
  "model_loaded": true,
  "version": "1.1.0"
}
```

### POST `/generate-diet-plan`
**Request Body**:

| Field | Type | Required | Notes |
|---|---|---|---|
| `target_calories` | float | yes | 500 to 7000 kcal |
| `protein_g` | float | yes | 10 to 500 g |
| `carbs_g` | float | yes | 10 to 800 g |
| `fats_g` | float | yes | 5 to 300 g |
| `fitness_goal` | string | no | Default "maintain weight". Words like "lose", "gain", "bulk" are detected |
| `days` | int | no | 1 to 30, default 3 |
| `exclude_food_ids` | list of int | no | Foods to skip (used for single slot regeneration) |
| `random_seed` | int | no | Makes the output repeatable for testing |

```json
{
  "target_calories": 2000.0,
  "protein_g": 150.0,
  "carbs_g": 200.0,
  "fats_g": 65.0,
  "fitness_goal": "lose weight",
  "days": 7
}
```

**Response**:
```json
{
  "status": "success",
  "fitness_goal": "lose weight",
  "days_count": 7,
  "target_daily_calories": 2000.0,
  "target_daily_macros": {
    "protein_g": 150.0,
    "carbs_g": 200.0,
    "fats_g": 65.0
  },
  "plan_days": [
    {
      "day": 1,
      "meals": {
        "breakfast": { ... },
        "lunch": { ... },
        "dinner": { ... },
        "snack": { ... }
      },
      "daily_totals": {
        "calories": 1994.5,
        "protein_g": 148.2,
        "carbs_g": 202.1,
        "fats_g": 63.8
      },
      "target_totals": {
        "calories": 2000.0,
        "protein_g": 150.0,
        "carbs_g": 200.0,
        "fats_g": 65.0
      },

        "protein_error_pct": 1.20,
        "carbs_error_pct": 1.05,

    }

```

Each meal slot contains `slot_name`, `items` (food_id, dish_name, portion_multiplier, portion_grams, calories, protein, carbs, fats), slot totals, slot targets, `weighted_loss` and `calorie_error_pct`.

**Error responses**: `400` for invalid parameters, `500` if model files are missing or plan generation fails.
